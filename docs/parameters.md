# Parameters

Every pipeline parameter, grouped as in `nextflow_schema.json` (the source of truth: parameters are validated against
it with nf-schema). This page is curated from `nf-core pipelines schema docs` plus guidance; a script check confirms
that it lists exactly the parameters of the schema.

Set parameters on the command line (`--name value`) or in a `-params-file params.yml`. Do **not** pass them through a
custom `-c` config (nf-schema validates params; see `CLAUDE.md`). Boolean flags accept `--x`, `--x true`, `--x false`
and `--x=false` (Nextflow >= 26.04 is required for this; see `main.nf`).

```bash
nextflow run charlesfoster/wasteline -profile docker \
    --mode full --input samplesheet.csv --outdir results \
    --primer_scheme midnight --barcodes latest
```

Run `nextflow run charlesfoster/wasteline --help` for the same list at the terminal (`--help_full`, `--show_hidden` for more).

## Modes (`--mode`)

| Mode        | Needs                                                             | Runs                                                                                               |
| ----------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `full`      | `--input` (FASTQ samplesheet)                                     | everything: fastp, bwa mem, ivar trim, freyja variants/demix/aggregate/plot, QC, consensus, report |
| `demix`     | `--input` (variants + depths) or `--previous_results`             | resolve Freyja data, `freyja demix`, aggregate/plot, QC from depths, consensus, report             |
| `aggregate` | `--input` (`.demix` files), `--demix_dir` or `--previous_results` | aggregate/plot and report                                                                          |
| `report`    | `--results_dir`                                                   | re-render the HTML report only                                                                     |
| `update_db` | `--db_dir` (optional)                                             | download the latest Freyja data into `--db_dir` and exit                                           |

The library options (`--protocol`, `--skip_primer_trimming`, `--duplicates`) act in `full`; `--protocol`, `--primer_scheme` and `--primer_bed` are the defaults for samples whose samplesheet `protocol` / `primer_scheme` cells are blank (see [usage](usage.md#mixed-libraries-in-one-run-per-sample-protocol-and-primer_scheme)); in `demix` only `--protocol` has an effect (amplicon coverage is never computed for `capture`).

Which parameters matter depends on the mode: the read-trimming and BAM options only act in `full`; the Freyja,
QC, consensus and report options act in `full` and `demix`; QC needs a primer scheme in `demix` for amplicon dropout.
The opt-in extras `--compare_barcodes`, `--freyja_boot` and `--annotate_variants` run in `full` and `demix` only (they
need variants/depths files; `--annotate_variants` also needs the consensus chain, so it does nothing with
`--skip_consensus`). `aggregate` uses only the aggregate/plot and report options; `update_db` only `--db_dir` (and
`--pathogen`).

The schema has **140 parameters** (the table rows below are checked against it by a script, in both directions).

## Library protocol

How the reads were made: PCR amplicons (primer-trimmed) or probe capture (not trimmed). See
[usage.md](usage.md#probe-capture-data-eg-twist---protocol-capture).

| Parameter                | Type                               | Default    | Description                                                                                                                                                                                                                                                                                                 |
| ------------------------ | ---------------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--protocol`             | string: `amplicon` \| `capture`    | `amplicon` | Library protocol. `amplicon`: tiled PCR amplicons, reads are primer-trimmed. `capture`: probe-capture libraries (e.g. Twist): no primer trimming, no amplicon-dropout analysis, PCR duplicates marked. With `capture`, `--primer_scheme` and `--primer_bed` are ignored (with a warning).                   |
| `--skip_primer_trimming` | boolean                            | `false`    | Do not primer-trim (`ivar trim`). For reads that are already trimmed. Implied by `--protocol capture`. Amplicon-level QC is off too: `--primer_scheme`/`--primer_bed` are ignored.                                                                                                                          |
| `--duplicates`           | string: `auto` \| `mark` \| `none` | `auto`     | PCR-duplicate handling after alignment. `mark`: flag duplicates (`samtools markdup`); Freyja's pileup then ignores them. `none`: leave them. `auto`: `mark` for `--protocol capture`, `none` for `amplicon`. Duplicates are flagged, never removed. Not used by modes without reads (`demix`, `aggregate`). |

## Panel options

Several targets (pathogens) in one run. **In development:** the parameters and the panel files are validated, but a run with
`--panel` stops with a message that panel runs are not implemented yet in this build. The panel file format is described in
[usage.md](usage.md#panels-in-development).

| Parameter                  | Type    | Default | Description                                                                                                                                                                                                                                                                                                |
| -------------------------- | ------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--panel`                  | string  | none    | A built-in panel name (`rsv`: RSVa, RSVb; `flu`: H1N1, H3N2, H5Nx, FLU-B-VIC) or the path to a panel CSV (a `target` column naming rows of `assets/panels/registry.csv`, plus optional override columns). Cannot be combined with `--pathogen`, `--fasta`, `--gff`, `--freyja_contig` or `--whole_genome`. |
| `--targets`                | string  | none    | Comma-separated targets of the results of a panel run that modes `demix`, `aggregate` and `report` use (default: all). Not used by `--mode full`.                                                                                                                                                          |
| `--panel_min_fragments`    | integer | `100`   | A target is detected in a sample only with at least this many read fragments assigned to it. A target below a threshold but with some fragments is `trace` (listed, not analysed). Thresholds are not calibrated on real data yet.                                                                         |
| `--panel_min_breadth_pct`  | number  | `5`     | A target is detected only if at least this % of its marker sequence is covered by its fragments.                                                                                                                                                                                                           |
| `--panel_family_share_pct` | number  | `5`     | Within a family (RSV, influenza A) a target that is not the top one is detected only with at least this % of the family's fragments (guards against cross-mapping between close relatives).                                                                                                                |
| `--panel_mapq`             | integer | `10`    | A read fragment is assigned to a target only if all its mapped reads have at least this mapping quality on the target's contigs.                                                                                                                                                                           |

## Parameters that are not on the command line

- `process.resourceLimits` (cpus, memory, time) is set in `nextflow.config` to the machine's size (memory 90 %), so
  the defaults run on a laptop. Override it with `process.resourceLimits` in a `-c` config (resources are not
  pipeline params, so a custom config is fine for them).
- Per-process resources come from the labels in `conf/base.config`; each attempt multiplies memory and time by
  `task.attempt`, and only exit codes 104, 130-145 and 175-177 (out of memory or killed) are retried once, everything
  else finishes the run without starting new tasks (steps that must never fail a run use `errorStrategy 'ignore'`
  and record a status instead):

  | Label            | CPUs | Memory | Time |
  | ---------------- | ---- | ------ | ---- |
  | `process_single` | 1    | 4 GB   | 4 h  |
  | `process_low`    | 2    | 4 GB   | 4 h  |
  | `process_medium` | 4    | 8 GB   | 8 h  |
  | `process_high`   | 8    | 16 GB  | 16 h |

  `BWA_MEM` is `process_high`; `FASTP`, `IVAR_TRIM`, `SAMTOOLS_SORT` are `process_medium`; `FREYJA_VARIANTS`,
  `FREYJA_DEMIX` (also the `--compare_barcodes` run) and `SAMTOOLS_VIEW` are `process_low`; the rest (including
  `FREYJA_BOOT`, `BARCODE_COMPARE`, `ANNOTATE_VARIANTS`) are `process_single`.

  Override per process with `process { withName: 'FASTP' { cpus = 8 } }` in a `-c` file.

- Container engines are chosen with `-profile docker|singularity|apptainer|podman|conda|mamba`; add `locked` to use
  digest-pinned images (`-profile docker,locked`), and `test`, `test_stub`, `test_full` for the bundled tests.
