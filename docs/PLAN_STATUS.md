# Plan status

A candid map from [PLAN.md](PLAN.md) to what exists in the repository at `0.1.0dev`, after the final implementation
round. Status was established by reading the code, the schema and the tests, and by an independent end-to-end run on the
synthetic dataset (Freyja 2.0.5, Nextflow 26.04.6, Docker, linux/amd64): a `full` run with `--compare_barcodes
container --freyja_boot --annotate_variants`, then `demix` and `aggregate` runs on its results, a `demix` run on a
legacy-layout copy, an `aggregate --demix_dir` run and a `report` run (all passed their output checks, exit 0). The
pytest suite is deliberately small (about 90 tests; see [development.md](development.md#the-test-layers)). "Implemented" means it exists in the code and ran; it does not
mean every edge case is tested on real data (the only dataset is synthetic, see [test_data.md](test_data.md)).

- **implemented**: present and exercised.
- **partial**: present with a stated gap.
- **not implemented**: not in the code or schema.

"E2E" below means the end-to-end run just described. nf-test results quoted are from the integration round's logs and
were not re-run for this page.

Note on the feature list: PLAN.md says "feature list F1-F20" was approved but itemises only some of the numbers. The
original proposal is not in the repository, so the meanings of **F4, F9 and F18-F20 are reconstructed** from the text of
PLAN.md (F4 expose the Freyja knobs, F9 bundled primer schemes, F18 drop the `--legacy` QC names, F19 MultiQC optional,
F20 agent files copied) and should be treated as best effort.

## Other deviations from PLAN.md worth knowing

- **File contracts changed from PLAN 6a**: `demix_status.tsv` has six columns (`sample, status, reason, genome_coverage_pct,
barcode_version, barcode_version_iso`) and a fourth status `missing`; `freyja_aggregated.tsv` has a `pathogen` column;
  the published `qc_summary.tsv` is **complete** (the `demix_*`, `consensus_*` and `barcode_version` columns are filled by
  the report builder; the QC script's own output still has `NA`). New files: `freyja_aggregated_controls.tsv`,
  `freyja_boot_summary.tsv`, `barcode_compare.tsv`, `barcode_compare_status.tsv`, `annotated_variants.tsv`.
- **`run_info.json`** has extra keys: `profile`, `command_line`, `run_name`, `containers`, `run_completed`, `duration`,
  `success`, `freyja_data_compare` (with `--compare_barcodes`) and (aggregate mode) `freyja_data_note`.
- **Parameters not in PLAN**: `--include_negatives_in_aggregate` (in PLAN D8), `--freyja_plot_interval`,
  `--freyja_plot_windowsize`, `--freyja_boot_seed`, `--qc_min_depth`, `--qc_pass_min_pct`, `--qc_fail_below_pct`,
  `--qc_max_dropped_amplicons`, `--results_dir`, `--demix_dir`. 76 parameters in total.
- **`--qc_max_dropped_amplicons` defaults to 1** in the pipeline while `bin/qc_summary.py`'s own `--max-dropped` default is 10
  (documented in [qc_scripts.md](qc_scripts.md)). For 99-amplicon ARTIC schemes the pipeline default is strict.
- **Mode `aggregate`** has no QC (the report has no QC, coverage, amplicon or consensus panels) but does have the time
  series when dates are known; mode `demix` does not re-publish the variants and depths files.
- `RENDER_REPORT` runs in a dedicated image (Python 3.12.12 + Jinja2 3.1.6) built from its `environment.yml` with the Seqera
  Wave CLI into Seqera's community registry (`community.wave.seqera.io/library/python_jinja2:b2615084ab562e7a`, plus the
  `oras://` Singularity build); `BUILD_REPORT_DATA` uses the plain Python image.
- Not in the plan, but present: `-profile locked`, the `results_input` subworkflow, `bin/check_samplesheet.py`, the
  `freyja_aggregated_controls.tsv` and the report's "Negative controls" section.
- `nextflow.config` `manifest.defaultBranch` is `main`.
